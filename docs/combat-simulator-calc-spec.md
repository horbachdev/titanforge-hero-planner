# Combat Simulator Calc Spec

This document is the parity gate for the quest simulator. The simulator must not be built from UI assumptions. Every function below is derived from raw Ress workbook formulas and must be covered by fixtures before the renderer calls it.

## Source Artifacts

- Workbook: `data/raw/ress-hero-quest-simulator.xlsx`
- Raw formula dump: `data/raw/ress-formula-dump.json`
- Formula index: `docs/ress-formula-index.md`
- Fixture truth rows: `data/fixtures/combat-simulator-cases.json`

The formula dump is generated by:

```bash
pnpm.cmd dump:ress-formulas
```

## Implementation Boundary

The first simulator module should be pure TypeScript, with no React or Electron dependency:

```ts
calculateEnemyDamagePerHit(input): number
calculateSimpleQuestTargeting(input): SimpleQuestTargeting
calculateHeroSoloQuestSummary(input): HeroSoloQuestSummary
calculateChampionRessStats(input): ChampionRessStats
runSeededQuestSimulation(input, rng): QuestSimulationResult
```

The UI may format these values, but must not contain combat math.

## Excel Rounding

Current audited formulas use positive values, so these helpers are enough for the first parity tests:

```ts
roundExcel(value) = Math.round(value)
roundupExcel(value) = Math.ceil(value)
rounddownExcel(value) = Math.floor(value)
```

If later formulas can produce negative intermediate values, Excel parity must be rechecked because Excel `ROUNDUP` rounds away from zero.

## Quest Simple Analysis

Source cells:

- `Quest Sim!G16:G20`
- `Quest Sim!H16:H20`
- `Quest Sim!I16:I20`
- `Quest Sim!C21`
- `Quest Sim!H21`

Raw formula, row 16:

```excel
ROUND(IF(D16<=$F$11/6,1.5*$E$11+(D16-0)/($F$11/6-0)*(0.5*$E$11-1.5*$E$11),IF(D16<=$F$11/3,0.5*$E$11+(D16-$F$11/6)/($F$11/3-$F$11/6)*(0.3*$E$11-0.5*$E$11),0.3*$E$11+(D16-$F$11/3)/($F$11-$F$11/3)*(0.25*$E$11-0.3*$E$11))),0)
```

Named form:

```ts
function enemyDamagePerHit(heroDefense, questAttack, questDefenseCap) {
  if (heroDefense <= questDefenseCap / 6) {
    return roundExcel(linear(heroDefense, 0, questDefenseCap / 6, 1.5 * questAttack, 0.5 * questAttack));
  }

  if (heroDefense <= questDefenseCap / 3) {
    return roundExcel(
      linear(heroDefense, questDefenseCap / 6, questDefenseCap / 3, 0.5 * questAttack, 0.3 * questAttack)
    );
  }

  return roundExcel(
    linear(heroDefense, questDefenseCap / 3, questDefenseCap, 0.3 * questAttack, 0.25 * questAttack)
  );
}
```

Important: the workbook formula does not explicitly clamp values above `questDefenseCap`. The third segment extrapolates unless a hidden upstream constraint prevents it.

The party-level helper formulas are:

```ts
teamAttackNoCrit = sum(party.attack);
totalEnemyHits = roundupExcel(questHp / teamAttackNoCrit);
targetPercent = heroThreat / sum(party.threat) * 100;
targetedHits = roundupExcel((targetPercent / 100) * totalEnemyHits);
survivesSimple = targetedHits * damagePerHit < heroHp ? "YES" : "NO";
```

## Quest Metadata

Ress `Quest Data` provides the simulator-specific columns the official quest import does not expose in the same normalized shape:

- `Quest Data!C:C`: LCoG flag
- `Quest Data!D:D`: Boss flag
- `Quest Data!E:E`: AoE chance
- `Quest Data!J:M`: Defense cap by difficulty
- `Quest Data!R:U`: AoE damage by difficulty
- `Quest Data!V:Y`: Barrier HP by difficulty
- `Quest Data!Z:AB`: Barrier element options

Official quest rows remain the baseline for IDs, party size, power requirement, enemy HP/ATK, and current release coverage. Ress quest rows enrich matching official quests and add missing simulator-only/event rows such as Lost City of Gold.

## LCoG Slot Limit

Ress intro text states that the fifth Hero slot is only used for LCoG quests. The app therefore keeps the roster model at up to five heroes, but the combat engine limits active hero slots by quest:

```ts
activeHeroSlots = quest.lcog ? 5 : min(4, quest.partySize || 4);
```

The Champion is tracked separately from these hero slots.

## AoE Quick-Analysis Approximation

Ress exposes AoE damage and AoE chance on `Quest Sim!G11:H11`, sourced from `Quest Data`. The exported workbook does not expose the random Full Analysis chain as formulas, so the MVP quick result applies AoE as deterministic expected damage:

```ts
expectedAoeDamage = roundExcel(questAoeDamage * questAoeChance / 100 * totalEnemyHits);
totalExpectedDamage = targetedHits * damagePerHit + expectedAoeDamage;
survivesQuick = totalExpectedDamage < heroHp;
```

This is not full Monte Carlo parity. It is a visible pressure estimate until the random AoE roll chain is mapped from Ress.


Default workbook fixture:

```ts
enemyDamagePerHit = 118;

```

This covers damage amount only. It does not define when an enemy critical hit occurs.

## Full Analysis Export Audit

Audited on the exported Ress V9.4 XLSX:

- `Quest Sim!A25:H32` are stored values, not formulas.
- The workbook contains no `RAND` or `RANDBETWEEN` formulas in `Quest Sim`.
- There are no hidden sheets containing the random simulation chain.
- The visible intro text says the simulator runs 50,000 quests and accounts for dodging and critical hits, but the exported XLSX does not preserve that logic as formula text.

Implication: full Monte Carlo parity cannot be implemented from the current exported XLSX alone. The next required source artifact is either:

- raw formula text from the live Google Sheet with formulas shown/exported before calculation is flattened, or
- manually captured known input/output rows across controlled scenarios sufficient to infer and validate the random event chain.

Until that source exists, Enemy Crit Chance, exact Evasion rolls, exact AoE rolls, target retargeting after deaths, and full-party success percentages must remain marked as pending.

```excel
Champion 1!AY5 = if(B19=1,0.05,if(B19=2,0.1,if(B19=3,0.25,0)))
```

Named form:

```ts
championSoulRowOffset = championSoulEnabled ? 2 : 0;
championSoulMultiplier = championSoulEnabled ? 1.5 : 1;
championElementBonus = elementTier === 1 ? 0.05 : elementTier === 2 ? 0.1 : elementTier === 3 ? 0.25 : 0;

championHp = roundExcel(
  (rankHpTable[rank + championSoulRowOffset][champion] * championSoulMultiplier +
    levelHpOffset[champion][level] +
    hpSeeds +
    familiarHp +
    auraSongHp) *
    (1 + auraSongHpPercent / 100 + championElementBonus)
);

championAttack = roundExcel(
  (rankAttackTable[rank + championSoulRowOffset][champion] * championSoulMultiplier +
    levelAttackOffset[champion][level] +
    attackSeeds * 4 +
    familiarAttack +
    auraSongAttack) *
    (1 + auraSongAttackPercent / 100 + championElementBonus)
);

championDefense = roundExcel(
  (rankDefenseTable[rank + championSoulRowOffset][champion] * championSoulMultiplier +
    levelDefenseOffset[champion][level] +
    defenseSeeds * 4 +
    familiarDefense +
    auraSongDefense) *
    (1 + auraSongDefensePercent / 100 + championElementBonus)
);
```

Gear cap formulas visible in `Champion 1!AU20:AY20` show that enchant-derived stat additions are capped against item base stats:

```excel
Champion 1!AU20 = (ROUND(AT20*AS20,0)+min(BB20,AT20)+min(BE20,AT20))
Champion 1!AW20 = (ROUND(AV20*AS20,0)+min(BC20,AV20)+min(BF20,AV20))
Champion 1!AY20 = (ROUND(AX20*AS20,0)+min(BD20,AX20)+min(BG20,AX20))
```

Named form:

```ts
finalGearAttack = roundExcel(baseAttack * qualityMultiplier) + min(elementAttack, baseAttack) + min(spiritAttack, baseAttack);
finalGearDefense = roundExcel(baseDefense * qualityMultiplier) + min(elementDefense, baseDefense) + min(spiritDefense, baseDefense);
finalGearHp = roundExcel(baseHp * qualityMultiplier) + min(elementHp, baseHp) + min(spiritHp, baseHp);
```

The exact source columns for `elementAttack`, `spiritAttack`, and related values still need to be mapped from `Champion 1` and `Skill Data` before implementing champion gear parity.

## Initial Fixture Policy

The first simulator tests must use `data/fixtures/combat-simulator-cases.json`.

Required behavior:

- Deterministic formula fixtures must pass exactly.
- Stored Monte-Carlo workbook outputs can use tolerance-based comparisons, but only after the random column chain is mapped.
- UI tests come after pure function tests.
- No simulator UI is accepted until the pure function parity tests are green.

## Open Formula Gaps

- The random simulation region behind `Quest Sim!A25:H32` is not yet mapped as formulas in the exported workbook.
- Enemy critical-hit chance/damage, evasion rolls, barrier damage, rest time, Polonia loot, boss/extreme branches, and conditional spirits need separate fixture groups.
- Hero stat parity still needs the full hidden chain from `Hero 1!AA140:BK144`, not only visible outputs.
- Champion gear affinity and capped enchant branches need exact column mapping from `Champion 1` and `Skill Data`.
